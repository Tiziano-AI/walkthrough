# Product vision

## The job

Give an authoring agent the expertise and executable tools to introduce a real
web product through an authentic narrated film. The viewer understands what
the product enables, how its capabilities connect and how its defining
interactions work. A concrete example gives continuity; the product remains
the subject.

The creator supplies product, audience and intent. The agent explores, chooses
what to show, uses the real application, records, narrates observed behavior
and delivers a local film. Revisions use retained sources when the requested
change does not require new application evidence. The creator does not prepare
selectors, shot JSON, a script or a timeline.

A new web product changes the film project, not the software required to film
it. No adapter, executable scenario, API classifier or site-specific selector
package is part of the contract.

## The experience

Install the native plugin, complete setup with the agent, describe the intended
film and receive something watchable. The plugin carries authoring expertise;
the independently installed CLI carries tools. Neither is a substitute for the
other, and neither hides a planner or runtime inside a host's plugin cache.

The author learns the product before deciding the final narrative. A feature
list, a report about an example and a series of isolated control demonstrations
do not provide the experience of using a product. Choose defining interactions,
give them meaningful use and connect the visible response to the next useful
capability. Existing data is evidence, not a reason to rebuild or refresh the
application merely for filming.

The viewer's attention has a path: orientation, gesture, readable response and
the next capability. A camera move approaches a subject from established
context and settles for input. A pause gives the viewer something to follow,
read or compare; a stationary comparison can be right. Constant motion and
continuous speech are not synonyms for flow.

The result is the film first, with a local review page for playback, seeking,
transcript and precise feedback. Captions support the full-frame product.
Original exported files accompany the film when they matter to the journey;
an interactive-only product does not need an invented export requirement.

## Responsibility

The creator decides intent, consequential authority, account access, voice
preference and acceptance. The author owns exploration, evidence selection,
story, real input, canonical narration, framing and finishing. The runtime
executes bounded operations and retains their identities and outputs; it does
not make business judgments about arbitrary websites.

Application access, effects, evidence review and publication are distinct
permissions. A project brief records the mandate without creating permission.
A completed input is not application success. An uncertain effect calls for
observation of the original attempt, not another click under a new identity.

Setup selects the operator's actual tools, saved narrator and applicable
renderer-license assertion. A verified candidate is not active configuration
until applied. Runtime drift must be visible and reviewed. Dependency downloads
belong to deliberate installation, never ordinary authoring or composition.

An explicit project survives runtime updates and plugin removal. Sealed footage,
clocks, input evidence, audio and original artifacts support offline revision.
Changing narration, captions or camera must not repeat application work. The
product protects useful sources without demanding an indefinite archive of
every test movie or duplicate master.

## Principles

1. **The product is the subject.** An example connects its capabilities rather
   than replacing them with advice about the example.
2. **Truth precedes polish.** Actual interactions and observed responses
   constrain the narrative.
3. **The author absorbs technical work.** A small natural-language brief should
   suffice; a new site does not require new software.
4. **Retention enables correction.** Editorial revisions reuse sources and audio;
   uncertain effects are reconciled rather than repeated.
5. **One active path owns each job.** Native plugin guidance, independent CLI,
   generic browser and one renderer have distinct responsibilities.
6. **Quality is encountered.** Integrity, input completion, rendering, full
   playback and viewer understanding establish different facts.

## Scope and value tests

The initial platform is macOS Apple Silicon, web products, local Voices and a
single Remotion renderer. Qualified output is 1920×1080 at genuine 60 fps from
measured source motion, with live footage at 1×, natural speech and no imposed
film-duration budget. Pictures and narration have independent tracks. English
and Italian are explicit narration choices; the operator selects the default
voice during setup.

There is no native-app driver, GUI editor, permanent daemon, hosted TTS, music
or automatic publisher. Ordinary web browser networking is not exact-host
isolation. Walkthrough does not promise that every web authentication or native
file-picker workflow is available.

The decisive value test is a fresh author completing a useful walkthrough from
an ordinary product/audience/intent brief through the installed plugin and CLI,
outside this checkout, without a site recipe or creator babysitting. A request
for a written guide should not start a film. A revision should remain possible
with the application unavailable and unchanged speech reusable without its
historical synthesis runtime.

Full viewing and listening establish continuity, legibility, truthful behavior
and natural delivery. A viewer unfamiliar with the product should explain its
purpose, recognize its main working areas and understand how to begin its
defining interaction. [Quality](QUALITY.md) defines these gates without
promoting a rendered file or a passing suite into viewer acceptance.
